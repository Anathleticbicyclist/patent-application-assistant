# 权利要求书与说明书起草

## 一、权利要求的三条铁律

1. **独权=最小必要特征集**。少一个必要特征→保护不到；多一个非必要特征→白送地盘。判断方法：把独权每个特征都问「去掉它，方案还能实现发明目的吗？」能去掉的就是非必要，删。
2. **每个从权都必须有引用基础**。从权里出现的任何术语，要么在独权里已出现，要么在本从权内首次定义。「所述第一预设阈值」而独权没提阈值→形式缺陷。
3. **说明书必须支持每一条权项**。权项里出现的每个特征、每个数值范围，说明书里都要有对应记载（实施例或概括性描述）。中国实务对「概括超出原始公开范围」审查很严。

## 二、独权写法（四步）

### 第 1 步：定主体与类别
- 方法：`一种……方法，其特征在于，包括以下步骤：S1…S2…S3…`
- 装置：`一种……装置，其特征在于，包括：M1 模块，用于……；M2 模块，用于……`
- 系统/设备/介质：在方法权项之后平行布置，措辞改为「……包括处理器与存储器」「……存储有计算机程序」。

### 第 2 步：写必要步骤，只写「做什么」，不写「为什么」
- 反例（混入效果）：`S3、通过二次确认降低误报率，从而提高系统稳定性` —— 效果不进权项。
- 正例：`S3、在所述告警触发后的预设时间窗口内再次采集信号，若再次满足预设条件则输出告警`。

### 第 3 步：给「条件 + 动作」而非「功能名词」
- 弱：`S2、进行数据预处理`
- 强：`S2、按预设窗口长度对采集信号滑窗分段，并对每段执行去趋势处理`

### 第 4 步：检查上位化程度
- 上位过头→被现有技术覆盖：`通过算法识别异常`（等于什么都没说）
- 下位过头→容易被规避：`采用 3 层 LSTM，隐藏维 128`
- 合适：`通过时序模型对所述特征序列进行异常打分`（保留模型类属，不锁死结构）

## 三、从权梯度（四类，每类至少 1–2 条）

| 类型 | 作用 | 示例 |
|---|---|---|
| 细化类 | 把独权某步骤写细 | 「所述预设时间窗口为 0.5–5s」 |
| 替代类 | 覆盖 FEAT 表替代方案 | 「所述时序模型为 LSTM、GRU 或 Transformer 中的任一种」 |
| 场景类 | 限定应用场景 | 「应用于动力电池包的在线监测」 |
| 边界类 | 异常/降级处理 | 「当采集信号缺失超过 N 个周期时，切换至历史数据外推」 |

数量建议：1 项独权 + 6–12 项从权。**从权不是越多越好**——每项从权都要单独交费，且未使用的从权在无效程序里毫无价值。

## 四、多类别权项布置

方法权项之后，按同一发明构思布置：

```
1. 一种 X 方法……
8. 一种 X 装置，包括处理器和存储器，所述存储器存储有计算机程序，所述处理器执行时实现权利要求 1–7 任一项所述的方法。
9. 一种 X 系统，包括……（若装置权项不足以覆盖系统级实现）
10. 一种计算机可读存储介质，其上存储有计算机程序，所述程序被处理器执行时实现权利要求 1–7 任一项所述的方法。
```

注意：装置权项若用「用于……的模块」撰写，属于「功能性限定」，中国实务要求说明书中有对应结构/程序实现支撑，否则可能被认为得不到支持。

## 五、说明书四段式

### 5.1 技术领域
一句话，与交底书一致。

### 5.2 背景技术
- 客观描述现有技术，引用对比文件时写「公开号 CN……A 公开了……」。
- 指出缺陷，但**不要贬损具体企业**，也不要写「现有技术全都失败」。

### 5.3 发明内容
- 严格按权项逐条复述（这是形式审查重点：发明内容应与权项一一对应）。
- 「有益效果」段与交底书第 6 节一致，每条效果对应一个特征。

### 5.4 附图说明 + 具体实施方式
- 附图说明：`图1 为本发明实施例提供的系统架构图；图2 为……流程图。`
- 具体实施方式：先给**一个完整实施例**（把交底书的 S1–S3 展开成可执行的描述，含参数、条件分支、异常处理），再给 2 个以上变形实施例。
- 每个数值范围都要在实施例里出现一次，并说明「在一实施例中取……，在另一实施例中取……」——这是支撑从权数值范围的唯一方式。

## 六、正反例对照

| 场景 | 错误写法 | 正确写法 |
|---|---|---|
| 独权含效果 | 「……从而提高准确率」 | 删除效果，只留动作 |
| 独权含非必要特征 | 「……采用型号 A 的传感器采集」 | 「采集目标对象的运行信号」 |
| 从权无引用基础 | 从权写「所述第三阈值」但独权无阈值 | 改为「所述预设阈值」或在独权引入 |
| 说明书不支持 | 权项写「0.5–5s」，说明书只写「1s」 | 说明书补「可为 0.5s、1s、3s、5s 等」 |
| 功能性限定无支撑 | 装置权项写「优化模块」 | 说明书补该模块的具体算法与数据结构 |
| 术语不一致 | 权项「判定单元」，说明书「判断模块」 | 全文统一为「判定单元」 |

## 七、交付格式

```
一、权利要求书
1. ……
2. 根据权利要求 1 所述的方法，其特征在于，……

二、说明书
技术领域
背景技术
发明内容
附图说明
具体实施方式

三、说明书摘要（≤300 字，含技术问题、方案要点、主要用途）
四、摘要附图（指定一幅图）
```

提交前跑 `scripts/check_deliverable.py` 做机检（编号连续性、引用基础、术语一致性、实施例数量）。
