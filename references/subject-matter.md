# 分领域客体适格性与撰写要点

中国专利法第 25 条排除「智力活动的规则和方法」等客体。不同领域的「能不能申请」「怎么写才不被驳」差别很大，别用一套模板套所有行业。

用法：P1 结构化之后、P6 撰写之前，按领域读对应一节，确认三件事——**是否属于可授权客体、技术特征够不够、实施例撑不撑得住**。

---

## A. 软件 / 算法 / AI

**核心判据**（审查指南第二部分第九章）：权利要求必须解决**技术问题**、采用**技术手段**、获得**技术效果**。算法本身是数学方法，只有与具体技术领域结合、处理的是技术数据、输出的是技术结果，才可能授权。

**自检清单**

- □ 是否解决的是**技术问题**（性能、功耗、精度、稳定性、资源占用），而非**业务问题**（怎么收费、怎么排班、怎么推荐更赚钱）；后者大概率客体不适格；
- □ 处理的是否为**技术数据**（传感器信号、图像、语音、控制参数、设备状态 —— 是；用户偏好、订单金额、文本语义 —— 通常不是）；
- □ 输出的是否为**技术结果**（控制指令、设备参数、图像增强结果 —— 是；一个评分、一个推荐列表 —— 通常不是）。

**撰写要点**

- □ 权项里是否有硬件/系统落脚点：「一种……方法，应用于包括存储器和处理器的电子设备」或「由传感器采集……」；
- □ 每个算法步骤是否写清**输入是什么数据、怎么处理、输出什么**，而不是只写「通过神经网络模型预测」；
- □ 训练方法与使用方法是否**分开写权项**（训练数据、损失函数属于技术方案的一部分，但纯训练策略可能被视为非技术）；
- □ 是否避免纯功能性表述（「智能地」「自适应地」），落到可执行的步骤；
- □ 说明书里是否有**至少一个完整实施例**的算法流程 + 参数取值，否则权项概括没有支持（第 26 条第 4 款）；
- □ 是否给出算法流程图（含分支与异常路径）；
- □ 是否写明模型结构（层类型、输入输出维度、关键超参含义）；
- □ 是否记载训练数据（来源、规模、训练/验证/测试划分、标注口径）；
- □ 是否说明运行环境（硬件资源、框架、推理时延）；
- □ 是否绑定具体技术场景并处理技术数据/输出技术结果；
- □ 实施例是否给可复现参数取值，而非仅写「精度高/效果好」。

**常见驳回**：「权利要求 1 请求保护的方案未采用技术手段解决技术问题，属于专利法第 25 条第 1 款第（二）项规定的智力活动的规则和方法」。

## B. 商业方法 / 交互 / UI

- 纯商业模式（收费规则、分成比例、营销策略）→ 不授权；
- **带技术手段的**（支付安全校验、库存调度与设备联动、交互过程中的数据处理）→ 可以，但技术特征要写足；
- UI 交互：发明保护「交互方法 + 数据处理」，**外观设计**保护「图形用户界面」（需产品载体 + 静态图，动态 GUI 要提交变化过程图）；
- 常见错误：把「用户点了 A 就展示 B」写成权项，缺少数据来源与处理，被判为「人为规定」。

**判断**：把方案里所有「人做的决策」换成「系统自动执行」，如果剩下的仍然只是「按规则分发信息」，客体就悬。

## C. 机械 / 结构

客体几乎不构成障碍，**驳回集中在必要技术特征缺失与支持不足**。

- □ 独立权利要求是否包含**解决技术问题所必需的全部必要技术特征**：部件 + **连接关系** + **位置关系** + 必要的形状/材料；
- □ 「连接」是否写清是固定连接、转动连接、滑动连接、一体成型、螺纹连接 —— 只写「连接」会被认为不清楚（第 26 条第 4 款）；
- □ 是否写明相对运动关系（转动/滑动/摆动行程）；
- □ 是否写明装配顺序与配合关系；
- □ 附图与文字是否一一对应，同一部件全文同一标记、同一名称；
- □ 尺寸、角度、材料是否避免使用「约」「大致」等不确定用语；
- □ 实施例是否至少给一个完整结构 + 一个变形例，否则从权的「替换结构」没有支持。

| 附图标记 | 部件名称（全文唯一） | 连接/位置/运动关系 |

|  |  |  |

> 同一部件全文同一标记、同一名称。

**自检**：把独权画成一张装配图，图上每个部件都能在权项文字里找到，且每条连线都有对应的连接关系描述。

## D. 电子 / 通信 / 芯片

- □ 电路类是否写清**单元 + 信号流向 + 时序关系**，避免只堆功能名（「获取单元、判断单元、输出单元」会被认为功能性限定过宽）；
- □ 通信类协议流程是否写清**消息名称、发送方/接收方、触发条件、字段含义**；只写「协商」「同步」不够；
- □ 通信流程是否写明帧结构、字段含义、协议版本与所处协议层；
- □ 电路/芯片案是否区分结构权项与工艺权项；
- □ 芯片/工艺类是否将结构 + 工艺步骤分别申请；工艺参数范围是否有端点与中间值实施例；
- □ 实施例是否记载具体协议版本、帧/字段参数与部署场景；
- □ 创造性效果是否对应到具体协议改进，而非仅写「提高了效率」。

**标准必要专利（SEP）**：若方案将被写入 3GPP/IEEE 等标准，需在提案阶段就做**声明（declaration）**，并注意 FRAND 承诺；这属于商业与法律动作，本技能只能提示、不能代办。

**提示**：通信领域的对比文件极多，创造性论证必须落到「具体的协议改进带来的技术效果」，不能只说「提高了效率」。

## E. 医药 / 生物

**客体红线**：疾病的诊断方法、治疗方法（含外科手术、给药处置方法）在中国实践通常不属于可授权客体。交底阶段若落点是对人体/动物实施诊断或治疗步骤，须改写成：

1. **产品权利要求**（药物组合物、医疗器械/装置、试剂盒）；
2. **制药用途权利要求**（如「化合物 X 在制备治疗 Y 疾病的药物中的应用」）；
3. **体外检测方法**（不以有生命人体为对象、结果不直接给出诊断结论的可尝试，适格性以代理师确认为准）。

判据：专利法第 25 条第 1 款第（三）项（条文表述以代理师确认/现行文本为准）。

除上述红线外，客体一般不构成障碍，**驳回集中在充分公开与实验数据**。

- □ 说明书是否公开**如何制备、如何使用、如何验证效果**；药物权利要求是否有**实验数据证明技术效果**（不能只描述机理）；
- □ 是否在交底书阶段就把关键实验数据写进去（**补充实验数据**：审查指南允许申请后补充，但前提是原申请文件里**已记载了相应技术效果**、补充数据是用来说明该效果的，别留到答复时再补）；
- □ 生物材料是否需**保藏**并提供保藏证明；涉及序列表的是否按 WIPO 标准 ST.26 提交；
- □ 抗体/序列类：功能限定 + 序列结构是否匹配，避免「一种能结合 X 的抗体」这种纯功能限定。

**自检**：把实施例的数据表拿出来，问一句「不看这些数据，审查员能相信效果吗？」

## F. 化学 / 材料

- **马库什权利要求**：通式 + 取代基定义，所有变量都要有定义，且说明书要支持每个变量的取值；
- **数值范围**：写明端点，且实施例覆盖端点与中间值；只给一个点、权项却要一个区间 → 支持不足；
- **参数**：测量方法必须写清（用什么仪器、什么条件），否则参数无意义；
- 组合物：组分 + 含量范围 + 作用，含量单位统一。

**常见驳回**：「权利要求概括的范围过大，说明书仅给出少数几个具体化合物，无法支持」。

---

## 跨领域共性检查（写进 P8 质检）

1. 权项里的每个技术术语，说明书里都能找到定义或实施例；
2. 权项的每个「上位概括」，至少有一个下位实施例支撑；
3. 效果与技术特征有因果链（因为 A 所以 B），不是并列罗列；
4. 实施例之间必须有**实质差异**（参数、结构、路径），只改数值不算不同实施例。
